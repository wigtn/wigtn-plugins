# 화면 규칙 (layout)

모든 수치는 pt, 16:9 슬라이드 960 × 540pt(PowerPoint 와이드, 13.333 × 7.5in) 기준이다.
`scripts/layout.py`가 같은 숫자로 배치하고, 글자가 자리를 넘으면 빌드를 멈춘다. 숫자를 바꿀 때는
두 파일을 함께 고친다.

## 1. 격자

```
 0 ─────────────────────────────────────────────────────────── 960
 │ 48                                                     912 │
 │  표시(tags) · y14                    01 구간 이름 · y14 →  │  ← 머리
 │  제목 · y28 · 28pt Bold · 한 줄                            │
 │ ─────────────────────── 구분선 y76 ─────────────────────── │
 │  부제 · y86 · 16pt · 한 줄                                 │
 │                                                            │
 │  본문 영역  y128 – 480  (폭 864, 높이 352)                 │  ← 몸통
 │                                                            │
 │  출처 · y504 · 9pt                            12 ● · y503 │  ← 꼬리
 └──────────────────────────────────────────────────────────── 540
```

- 좌우 여백 48pt. 제목·부제·본문의 왼쪽 끝을 모두 x 48에 맞춘다. 제목을 가운데 정렬하지 않는다.
- 본문을 반으로 나눌 때는 그림 508 · 간격 32 · 근거 324(약 6 : 4). 두 칸 비교는 간격 40, 카드는 간격 24.
- 블록 사이 세로 간격은 18pt. 짧은 내용은 본문 영역의 위가 아니라 **위에서 42% 지점**(눈이 느끼는 가운데)에 놓는다.

## 2. 머리와 꼬리

| 요소 | 자리 (x, y, 폭) | 글자 | 규칙 |
|---|---|---|---|
| 구간 표시 | 480, 14, 432 · 오른쪽 정렬 | 10pt Bold, muted | `01  어디서 틀리나`. 번호만 강조색. 구간 안의 본문 장에만 |
| 표시(tags) | 48, 14, 432 | 10pt Bold, accent | `우리 제안 · 설명용 예시 · 한계` |
| 제목 | 48, 28, 864 | 28pt Bold, 줄 간격 1.15 | 한 줄. 넘치면 오류 |
| 구분선 | y 76, x 48–912 | 0.75pt, line | |
| 부제 | 48, 86, 864 | 16pt Regular, text2 | 한 줄. 넘치면 오류 |
| 출처 | 48, 504, 754 | 9pt, muted | 두 줄까지. 두 줄이면 위로 자란다 |
| 쪽 번호 | 812, 503, 100 · 오른쪽 정렬 | 10pt Bold, muted | WIGTN 테마는 번호 뒤에 시그니처 퍼플 점 |

표지·구간 표지·마무리는 머리 대신 자기 배치를 쓴다(아래 4절).

## 3. 글자 크기

Pretendard 두 굵기(Regular, Bold)만 쓴다. 한 장에 크기는 세 단계 안쪽.

| 역할 (`role`) | 크기 | 굵기 | 줄 간격 | 쓰는 곳 |
|---|---|---|---|---|
| cover_title | 40 | Bold | 1.15 | 표지 제목, 두 줄까지 |
| hero | 40 | Bold | 1.1 | 큰 숫자 |
| section_title · section_no · statement | 32 | Bold | 1.1–1.3 | 구간 표지, 한 문장 장 |
| title | 28 | Bold | 1.15 | 장 제목 |
| close | 26 | Bold | 1.3 | 마무리 문장 |
| quote | 24 | Bold | 1.35 | 인용 장 |
| cover_sub · map_label · col_head | 20 | Bold(부제는 Regular) | 1.25–1.3 | 표지 부제, 지도 단계, 비교 칸 머리 |
| heading · quote_sm | 18 | Bold | 1.3 | 소제목, 질문, 짧은 인용 |
| lead · head · body | 16 | lead·body Regular, head Bold | 1.3–1.35 | 부제, 항목 머리, 본문 |
| body_sm · label · event | 14 | label·event Bold | 1.3–1.4 | 근거 설명, 목록, 차트 제목 |
| sub | 13 | Regular | 1.3 | 지도·비교 칸의 보조 줄 |
| caption · note | 12 | Regular | 1.3 | 그림 설명, 큰 숫자 아래 설명 |
| meta | 10 | Bold | 1.2 | 구간 표시, 쪽 번호 |
| source | 9 | Regular | 1.3 | 출처 줄 |

- **청중이 읽어야 하는 글자는 14pt 이상.** 12pt는 그림·숫자에 붙는 설명, 9–10pt는 출처와 쪽 번호뿐이다. 이보다 작은 글자를 쓰면 오류.
- 줄바꿈은 Pretendard 실제 글자 폭으로 계산하고, 상자 폭의 96%까지만 채운다(렌더러 차이 여유).
- 한 줄 글자 수 가늠: 28pt 제목 한글 약 30자, 16pt 부제 약 52자, 324pt 칸의 14pt 본문 약 24자.

## 4. 레이아웃 16종

| layout | 쓰는 때 | 구성 | 한도 |
|---|---|---|---|
| `cover` | 표지 | 로고(48,44) · 강조 막대 · 행사·날짜(y164) · 제목 40pt(y192, 폭 760) · 부제 20pt · 발표자(y420) · 소속(y443). `visual`이 있으면 글자는 왼쪽 500, 그림은 오른쪽 | 제목 2줄(그림 있으면 3줄) |
| `map` | 지도(목차) | 단계 3–5개(case는 6개까지, 6개면 이름 16pt·간격 24)를 가로로. 단계마다 윗선 3pt · 번호 · 이름 20pt · 보조 13pt · 설명 14pt, 사이에 화살표 | 이름 2줄, 설명 3줄 |
| `section` | 구간 표지 | 위에 작은 지도(지금 단계만 강조) · 번호 32pt(y292) · 단계 이름 32pt · 이 구간이 답할 질문 18pt | 질문 2줄 |
| `visual-evidence` | 근거 장의 기본 | 왼쪽 그림 508×352(설명 12pt 포함) · 오른쪽 324 칸에 `side` 블록을 위에서 아래로. `flip`이면 좌우 반대 | `side` 전체가 344pt 안 |
| `chart` | 수치 비교 | 기본 차트 864 폭. `side`가 있으면 차트 560 + 오른쪽 272 | 가로 막대 1개당 24pt 이상 |
| `compare` | 두세 가지 비교 | 2–3칸, 칸 사이 세로선. 칸마다 머리 20pt(색 지정) · 보조 13 · 목록 14 · 큰 숫자 | 칸 높이 344pt |
| `cards` | 항목 나열, 결정 요청 | 2–4장. 카드 배경 surface, 안쪽 여백 24. 번호 14 · 머리 18 · 설명 14 · 큰 숫자 | 카드 높이는 가장 긴 카드에 맞춤(최소 160) |
| `kpi` | 큰 숫자 2–4개 | 가로로 나란히. 아래에 구분선과 한 줄(`foot`) | 숫자 1줄, 설명 2줄 |
| `quote` | 인용 | 왼쪽 강조 막대 · 인용 24pt · 출처 13 · 번역 18 | 인용 4줄 |
| `statement` | 한 문장 장, 브리핑 결론 | 문장 32pt(3줄까지) · 보조 18. 제목 없이도 쓴다 | 3줄 |
| `qa` | 입장, 예상 질문 | 왼쪽 540에 질문 18 + 답 14 · 오른쪽에 강조 세로선과 정리 목록 · 맨 아래 다음 질문(`bridge`) | 질문 3개 |
| `steps` | 과정, 순환 | `visual`이 있으면 왼쪽 그림 + 오른쪽 번호 목록, 없으면 가로 원 번호 3–6개 | 단계 3–6개 |
| `table` | 표 | 기본 표. 머리 행 surface 배경, 행마다 아래 선, 글자 14pt | 행 높이 합이 344pt 안 |
| `image` | 큰 그림 하나 | 그림 864×352(설명 12pt 포함) | |
| `close` | 마무리 | 작은 지도(마지막 단계 강조) · 마무리 문장 26pt · 연락처 14 | 문장 2줄 |
| `free` | 참고 이미지를 객체 단위로 다시 짤 때 | `elements`의 좌표 그대로. 글자는 `role`로 크기를 받는다 | 슬라이드 안, 글자 상자끼리 겹치면 오류 |

**역할별 추천**

| role | 먼저 고를 layout |
|---|---|
| context · claim · evidence | `visual-evidence`, `chart`, `compare` |
| counter | `chart`(나빠지는 숫자를 risk 색으로), `quote`, `kpi` |
| stance | `qa` |
| proposal | `steps`, `visual-evidence` |
| example | `free`, `visual-evidence`, `cards` |
| action · ask | `cards`, `table` |
| conclusion | `statement` |

같은 layout을 세 장 넘게 연달아 쓰지 않는다. 리듬이 죽는다.

## 5. 색의 뜻

테마 파일(`themes/*.json`)의 이름만 쓴다. HEX를 직접 쓰면 오류.

| 이름 | 뜻 | 쓰는 곳 |
|---|---|---|
| `text` | 기본 글자, 기존·확인된 것 | 제목, 본문 |
| `text2` | 보조 글자 | 부제, 설명 |
| `muted` | 읽지 않아도 되는 글자, 지금이 아닌 단계 | 출처, 쪽 번호, 지도의 다른 단계 |
| `accent` | **이 장의 초점, 우리가 미는 것** | 강조 막대, 큰 숫자, `==강조==` |
| `risk` | 위험·하락·실패 | 반론 장의 나쁜 숫자. 한 장에 한 곳 |
| `chart_base` | 비교 대상 | 강조하지 않는 막대와 선 |
| `surface` · `surface2` · `line` · `bg` | 면과 선 | 카드, 표 머리, 구분선, 배경 |

- 초점(accent)과 위험(risk)을 같은 색으로 쓰지 않는다.
- 한 장에서 accent를 쓰는 곳은 두 군데 안쪽. 모든 것이 강조되면 아무것도 강조되지 않는다.

## 6. 차트 규칙

- 차트는 pptx 기본 차트로 넣는다. 데이터가 파일 안에 함께 저장되므로 PowerPoint에서 값을 고칠 수 있다.
- `bar`(가로 막대): 항목 이름이 길 때. `column`(세로 막대): 3–6개 비교. `line`: 시간에 따른 변화.
- 막대: 강조할 막대(`highlight`)만 accent(또는 `tone: "risk"`), 나머지는 chart_base. 값은 막대 끝에 직접 적고 값 축은 숨긴다.
- 꺾은선: 강조 계열(`highlight: true`)은 굵은 실선, 나머지는 회색 점선. 끝값만 적는다. 축은 데이터 근처에서 시작한다(`zero: true`면 0부터).
- 차트 제목은 `무엇 (단위) · 표본` 형식: `Hit@5 (%) · 같은 질문 300개`.

## 7. 그림 규칙

- **숫자는 차트로만.** 손으로 그린 그림이나 비유 그림에 숫자를 넣지 않는다.
- **구조·흐름**: `architecture-diagram` 스킬로 PNG를 만들어 `{"kind": "diagram", "path": …}`로 넣는다.
- **비유 그림·아이콘**: SVG를 직접 그린다.
  - `visual-evidence` 왼쪽 칸이면 `viewBox="0 0 508 330"`처럼 칸 비율에 맞춘다.
  - 색은 `{{accent}}`, `{{text}}`, `{{surface}}`처럼 테마 이름으로 쓴다. 빌드할 때 테마 색으로 바뀌어서 같은 그림이 Light·Dark·중립에서 모두 맞는다.
  - SVG 안 글자는 14px 이상. 글자가 많으면 그림 대신 `side` 블록에 쓴다.
  - pptx에는 PNG와 원본 SVG가 함께 들어간다. PowerPoint에서 그림을 골라 "도형으로 변환"하면 객체 단위로 고칠 수 있다.
- **스크린샷**: 전체 화면을 줄여 넣지 않는다. 핵심 문장 부분만 잘라 넣고, 화면에서 글자가 12pt 이상으로 보여야 한다.
