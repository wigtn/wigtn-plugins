# 모션 가이드

씬을 새로 만들 때 이 규칙과 템플릿의 프리미티브를 조합하고 마지막에 체크리스트로 스스로 검토한다.
기준은 Remotion 4.x, 1920×1080, 30fps다. 아래 규칙은 실제 영상을 만들며 받은 지적에서 나왔다.

## 1. 방향

- 기능은 설명하지 않고 보여 준다. 화면만 봐도 무엇이 일어나는지 알 수 있어야 한다.
- 움직임은 시선을 옮기려고 쓴다. 꾸미려고 쓰지 않는다.
- 한 화면에서 볼 것은 하나다. 나머지는 가만히 둔다.

## 2. 꼭 지키는 규칙

1. 글자 크기: `paper-demo` 24px 이상, `showcase` 20px 이상(1080p 기준). 본문은 28px 이상, 자막은 34px.
   영상은 작게 줄여서 보는 일이 많다. 줄어든 화면에서도 읽혀야 한다.
2. 대비: 연한 회색 글자를 쓰지 않는다. 보조 글자도 `theme.sub`보다 흐리게 하지 않는다.
3. 카드는 불투명하게: 반투명 유리 효과를 기본으로 쓰지 않는다. `theme.surface` + 테두리가 기본이다.
4. 배경은 하나: 컴포지션 배경과 모든 씬 배경이 같은 색(`theme.bg`)이다. 전환 중에 다른 색이 한 프레임도 비치면 안 된다.
   어두운 테마에서 흰 화면이 번쩍이는 것이 가장 흔한 실수다.
5. 항상 easing: 일정한 속도로 움직이지 않는다. 시작과 끝이 갑자기 끊기지 않게 줄이며 멈춘다(`EASE.out`, `EASE.inOut`).
6. 가운데 정렬: 좌우 균형을 맞추고 여백을 넉넉히 둔다. 카드와 글자는 크게.
7. `useCurrentFrame()`만: 모든 움직임은 현재 프레임의 함수여야 한다. CSS animation·transition, `setTimeout`,
   `requestAnimationFrame`, three.js의 `useFrame()`은 렌더할 때 깜빡이거나 프레임마다 결과가 달라진다.
8. 발표 자료처럼 만들지 않는다: 굵은 화살표, 여러 색을 한꺼번에 쓰기, 번호 남발을 피한다. 강조색은 한 가지만.
9. 반복되는 장면은 이음매가 없어야 한다: 되돌아갈 때 요소가 튀거나 결과가 어긋나면 안 된다.
10. 다른 회사의 것을 넣지 않는다: 로고, 브랜드 색, 글꼴 파일, 음악. 쓸 권리가 분명한 것만 쓴다.

## 3. 토큰 (`src/theme.ts`)

| 이름 | 쓰는 곳 | dark | light |
|---|---|---|---|
| `bg` | 컴포지션과 씬 배경 | `#0e1116` | `#f3f4f6` |
| `surface` | 카드, 화면 창 | `#181d25` | `#ffffff` |
| `surfaceAlt` | 창 제목 줄, placeholder | `#222a35` | `#e9ecf1` |
| `border` | 테두리 | `#343e4d` | `#cfd5de` |
| `ink` | 주 글자 | `#f2f5f9` | `#12161d` |
| `sub` | 보조 글자 | `#b9c2cf` | `#444e5c` |
| `accent` | 강조 한 가지 | `#7fb2ff` | `#1f4fbf` |
| `captionBg` / `captionInk` | 자막 | `#05070a` / `#ffffff` | `#12161d` / `#ffffff` |

- 테마는 컴포지션의 `theme` prop으로 고른다(`Root.tsx`의 `defaultProps`, 또는 `--props='{"theme":"light"}'`).
- 제품 화면이 밝으면 `dark` 배경에서 창이 잘 떠 보인다. 제품 화면이 어두우면 `light`를 써 본다.
- 색을 바꿀 때는 `accent`만 바꾼다. 글자 크기는 `TYPE`, 자막 띠 높이는 `CAPTION_ZONE`에 있다.
- 글꼴은 Inter(`@remotion/google-fonts`, 렌더할 때 받는다)와 시스템 고정폭 글꼴이다.

## 4. 프리미티브

| 파일 | 내용 |
|---|---|
| `motion.tsx` | `EASE`(out · inOut · in), `ramp(frame, start, dur)` 0→1 진행값, `useEnter(delay)` 등장 진행값, `reveal(p)` 떠오르며 나타나기, `mix` |
| `transitions.tsx` | `dissolve()` 배경색을 거쳐 넘어가는 전환 |
| `Caption.tsx` | `Narration` 자막과 음성 층, `chunkText` 자막 나누기, `segFrames` 줄 길이 |
| `core.mjs` | 렌더러와 스크립트가 함께 쓰는 규칙: `planNarration`(narration 배치와 겹침 검사), `resolveAudio`(음성이 지금 대본과 맞는지) |
| `scenes/Title.tsx` | 여는 장: eyebrow, 제목, 한 줄 설명, 저자·소속 |
| `scenes/Footage.tsx` | 창 틀 안의 실제 화면, `zooms`로 확대, 빈 slot이면 placeholder |
| `scenes/Points.tsx` | 결과 카드 최대 3개: 값, 무엇을 잰 것인지, 출처 |
| `scenes/Outro.tsx` | 닫는 장: 이름과 찾아갈 곳 |

새 씬이 필요하면 이 프리미티브로 만든다. 요소는 `useEnter(delay)`의 delay를 6–10프레임씩 늦춰 차례로 나오게 한다.

## 5. 씬 구성

```
<AbsoluteFill bg=theme.bg, 아래 CAPTION_ZONE만큼 비움>
  제목이나 한 줄 주장      가운데, 크게
  보여 줄 것 하나          카드 · 화면 창 · 숫자
</AbsoluteFill>
자막 띠                    Narration 층이 맨 위에 따로 얹힌다
```

- 씬 내용은 자막 띠 위에서 끝난다. `Footage` 창은 y=902에서 끝나고 자막은 그 아래에 나온다.
- 타임라인은 `src/Demo.tsx`의 `SCENES`다. 씬 길이는 `S(초)` 한 줄이고 전환(`TR` 프레임)만큼 앞뒤 씬이 겹친다.
- 씬이 시작하는 프레임은 `SCENE_STARTS`에 있다. 스틸을 뽑을 프레임을 여기서 계산한다.

## 6. 전환

- 기본은 `dissolve()` 하나다. 나가는 씬이 앞 절반 동안 사라지고 들어오는 씬이 뒤 절반 동안 나타난다.
  두 씬의 글자가 겹쳐 보이지 않고 사이에 보이는 것은 같은 색 배경뿐이다.
- 씬을 1보다 작게 줄이거나 화면 밖으로 미는 전환은 뒤가 드러난다. 쓰려면 항상 화면을 덮는 크기로 만든다.
- 전환은 짧게(0.4–0.6초). 연출은 전환이 아니라 씬 안의 요소가 차례로 들어오고 나가는 것으로 한다.

## 7. 동작을 보여 주는 법

- 실제 화면을 `Footage`로 틀고 설명하는 부분으로 확대한다(`zooms`). 확대는 한 씬에 한두 번이면 충분하다.
- narration이 말하는 순서와 화면에서 일어나는 순서를 맞춘다. 말보다 화면이 반 박자 먼저 가면 따라가기 쉽다.
- 결과가 나온 화면에서 2초 이상 머문다.
- 구조를 설명해야 하면 한 장면으로 줄인다. 상자와 화살표를 여러 장 넘기지 않는다.

## 8. 프로필별 차이

### `paper-demo`

뺄 것:

- 3D, 입자, 빛 번짐 같은 장식
- 효과음과 배경 음악
- 브랜드 인트로, 로고 애니메이션
- 화면이 튀어 오르는 spring, 빠른 줌, 흔들림
- 과장하는 문구

남길 것:

- easing (모든 움직임)
- 1080p에서 24px 이상의 글자
- 설명하는 영역으로의 확대와 잘라 보여 주기
- 자막이 설명 중인 UI 영역을 가리지 않는 배치
- 숫자 옆의 출처(`Points`의 `source`)

실제 화면 녹화가 길이의 대부분을 차지하게 한다. 여는 장과 닫는 장은 짧게.

### `showcase`

- 위 장식 중 일부를 써도 된다. 2절의 규칙은 그대로 지킨다.
- 음악이나 효과음을 넣으려면 쓸 권리가 있는 것만 쓰고 음성보다 작게 깐다.
- 움직임이 많아질수록 스틸로 확인할 프레임도 늘린다.

## 9. 스틸 검토

전체 렌더는 느리다. 조합하고 주요 프레임을 스틸로 뽑고 체크리스트로 보고 고친다. 전체 렌더는 마지막에 한 번만 한다.

```bash
npx remotion still Demo out/s-title.png --frame=70 --log=error
npx remotion still Demo out/s-light.png --frame=70 --props='{"theme":"light"}' --log=error
npx remotion studio                    # 사람이 직접 볼 때
```

뽑을 프레임: 씬마다 요소가 다 나온 뒤 한 장, 확대가 끝난 순간 한 장, 전환 한가운데 한 장, 가장 긴 자막이 나오는 순간 한 장.

## 10. 체크리스트 (씬이 끝났다고 말하기 전에)

- [ ] 모든 글자가 프로필의 최소 크기 이상이고 흐린 회색 글자가 없다
- [ ] 잘리거나 넘친 글자가 없다. 자막은 두 줄 이하다
- [ ] 자막이 설명 중인 화면 영역을 가리지 않는다
- [ ] 카드가 불투명하고 배경색이 씬마다 같다
- [ ] 가운데 정렬과 좌우 균형이 맞고 여백이 넉넉하다
- [ ] 모든 움직임에 easing이 있고 시작과 끝이 끊기지 않는다
- [ ] 전환 한가운데 프레임에 다른 색이나 겹친 글자가 없다
- [ ] 확대한 화면이 흐리지 않고 설명하는 부분이 가운데 있다
- [ ] 화면만 봐도 무엇이 일어나는지 알 수 있다
- [ ] 화면의 숫자마다 출처가 있고 사실 확인 표와 같다
- [ ] 비밀 값, 개인정보, 다른 회사 로고가 없다
- [ ] 빈 capture slot(placeholder)이 남아 있지 않다
- [ ] `paper-demo`: 3D, 효과음, 브랜드 인트로, 과장하는 문구가 없다
